# 激励金额自助查询 · 原型说明（v2：按三张原表结构升级）

## 本次升级内容（相对 v1）
- **数据结构对齐原表**：数据源改为三个 Sheet（试驾激励 / 交付激励 / 终端激励），列名与三张原表**完全一致**，只在末尾多一列「月份」——三张原表内容可整列直接粘贴，不再需要手工映射到统一结构。
- **一把钥匙查全部**：查询页只有一个输入框，系统自动识别输入的是店代码（15位以内编码）还是身份证号（15/18位），一次查回三类激励：
  - 店代码 → 匹配 试驾「经销商编码」+ 交付「经销商代码」+ 终端「店编号」
  - 身份证 → 匹配 试驾/交付「身份证」+ 终端「总经理身份证」
- **留痕升级**：每次查询记录 时间 / 查询方式 / 店代码或掩码身份证 / **查询人姓名（选填）** / 月份 / 是否查到 / 条数 / 合计金额 / 该键累计第几次，写入 `data/query_log.csv`。
- **去掉导出**：页面无任何导出/打印按钮，且打印样式下整页隐藏（Ctrl+P 打不出内容）。

## 已交付内容
- **查询网页**：`index.html` — 单输入框自动识别钥匙，结果按三类激励分组展示（各组含原表关键列 + 小计），顶部合计。
- **查询后端**：`app.py` — 仅服务端读明细表；完整身份证只在服务端比对、永不下发浏览器（门店查询结果给掩码便于店内核对）；文件替换后按 mtime 自动重载；无任何导出接口。
- **示例数据**：`data/incentive_sample.xlsx`（三个 Sheet，14 行虚构数据）+ 三个同名 CSV 保底。
- **数据模板**：`data/激励明细模板.xlsx`（填写说明 + 三个 Sheet 各带 1 行示例）。
- **转换工具**：`convert_csv.py`（xlsx 三 Sheet → 三个同名 CSV，依赖装不上时的保底）。

## 访问方式
- 线上链接（WorkBuddy 内发布）：发布后打开链接即用；外部浏览器访问受限属平台特性。
- 本地自测：`python app.py` 后访问 `http://127.0.0.1:3000`。

## 你每月要做的（投喂真实数据）
1. 打开 `data/激励明细模板.xlsx`，把当月三张原表分别整列粘贴进对应 Sheet，末列「月份」填 2026-09 这种格式。
2. 覆盖 `data/incentive_sample.xlsx`（Sheet 名保持不变），重新发布即生效，无需改代码。
3. 查留痕：打开 `data/query_log.csv`（Excel 直接打开）。

## 隐私与安全要点
- 完整身份证只在服务端留存比对，前端永不显示完整号码。
- 前端只拿到「本店/本人」匹配行，无法拉取全表；无导出/打印能力。
- 查不到统一提示「联系渠道赋能科核对」，不暴露是否存在该人。
- 每次查询写入 `data/query_log.csv`，含累计查询次数，可审计。
